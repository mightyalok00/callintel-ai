# Evaluation protocol: emotion, dataset integrity, and independently annotated speech

## 1. MELD split integrity and provenance

Run `python training/validate_meld_splits.py` before model evaluation. The validator checks expected official partition sizes (train: 9,989 utterances/1,038 dialogues; dev: 1,109/114; test: 2,610/280), required turn fields, emotion labels, duplicate turn IDs inside a dialogue, exact duplicate multi-turn dialogue content across partitions, and SHA-256 hashes of the processed JSON files. MELD Dialogue_ID values are local to each partition; raw IDs are never compared across train/dev/test.

For independent source-to-processed provenance validation, place the original official files at `data/meld_raw/{train,dev,test}_sent_emo.csv`. If all three exist, the validator compares each CSV row and dialogue grouping to its corresponding processed JSON. If they are absent, the report explicitly says upstream provenance is not fully verified. Structural checks and local file hashes do not prove upstream authenticity.

## 2. Held-out emotion evaluation

Run `python training/evaluate_ml_models.py`. TF-IDF word uni/bigrams are fitted on official train only; the official held-out test partition is scored once. The report includes majority-class accuracy and macro-F1, model accuracy/macro/weighted F1, per-class precision/recall/F1, confusion matrix, and 95% dialogue-bootstrap intervals. Dialogue bootstrap preserves within-dialogue dependence. If model macro-F1 does not exceed the majority baseline, report that honestly; do not treat passing CI as evidence that the model is useful. This is scripted television dialogue, not call-center emotion recognition.

The quality workflow uploads the generated JSON and Markdown reports and writes the held-out results and per-class F1 table to the GitHub Actions job summary. These are generated from that run, not copied from stale checked-in metrics.

## 3. Independently annotated speech test set

No independent human-annotated real-call audio is currently included. Therefore this repository must not claim real-world WER or DER. To create a valid evaluation set, obtain consented and de-identified calls, freeze call-level test membership before tuning, and have annotators who do not see model predictions independently create:
- exact reference transcripts, with a documented normalization policy;
- speaker-turn start/end times and speaker IDs in RTTM;
- annotation adjudication notes and call metadata (noise, codec, accent, overlap).

Keep audio and PII out of Git. Store the corpus in approved private storage and provide only paths to the scoring commands. Do not substitute generated sample calls for independent ground truth.

### WER with call-level 95% bootstrap CI

Create UTF-8 JSONL where each row has `call_id`, `reference`, and `hypothesis`. The reference must be human-verified and the hypothesis must be generated by the evaluated system without reference access.

```bash
python training/score_asr.py --input /secure/path/asr_eval.jsonl --bootstrap 2000 --seed 42
```

The scorer reports aggregate corpus WER and a 95% percentile bootstrap interval by resampling calls. It fails on missing/empty references and does not fabricate scores.

### DER with recording-level 95% bootstrap CI

Create reference and hypothesis RTTM files with matching recording IDs. Install optional dependencies and run:

```bash
python -m pip install -r requirements-speech-eval.txt
python training/score_diarization.py --reference /secure/path/reference.rttm --hypothesis /secure/path/hypothesis.rttm --collar 0.25 --bootstrap 2000 --seed 42
```

DER is scored by `pyannote.metrics`; the interval resamples whole recordings and reports macro-average recording DER. Always publish the collar and overlap policy. A CI interval requires multiple independently annotated recordings; if there is only one recording, the script reports that a meaningful recording-level CI is unavailable.

## 4. Reproducibility

The quality workflow uploads JSON/Markdown reports as artifacts. Record commit SHA, Python version, dependency versions, source dataset checksums, split membership, scoring options, and the exact command output. Never replace missing annotations with synthetic labels or call a missing metric zero.
